# 亚马逊商品图制作

先定位用户要做的 SKU、变体和本次要交的东西。已有目录时优先使用其档案、任务清单和已选版本。在当前 SKU 工作目录保留相应资料，使用[制作卡与模板](references/制作卡与模板.md)中与本次任务对应的部分。

## 选择本次入口

| 用户任务 | 从哪里开始 | 这次应实际交回 |
|---|---|---|
| 策略、运营拆图、提示词 | 读取产品事实、实拍、运营要求，按买家问题拟图序 | 图序、画面依据与所需制作卡。止于用户指定的策划阶段。 |
| 做一张或整套图 | 读取资料及已有卡；确定规格、画面、参考实拍 | 调用可用的图片生成或编辑能力，实际保存输出，逐张观察后交图。 |
| 修改某一张或改规格 | 定位图号、已选版本与实际底图，明确改什么、保留什么 | 局部编辑出新版；仅改尺寸或格式时按指定适配方式导出。保留旧版、给前后对照。 |
| 续做、核对、交付 | 查看任务和已存版本，读取最近反馈或交接记录 | 继续相应待办，或列出能打开的交付文件、版本、规格和未解决项。 |

## 执行

1. **建档一次。** 以当前 SKU 的实拍和可追溯的产品资料为依据。把实售颜色、结构、尺寸及适配的实测值和来源写入档案，区分估计值。将竞品、运营批注、草图及自有图分别标记。遇到会改变画面的冲突，只阻塞受影响的图。按用户指示使用竞品资料；原则上以分析所得的版式和光线描述指导构图，选择自有实拍作产品参考。
2. **按用途拆图。** 保留运营要求的图号；需要独立提案时，说明每个买家疑问由哪种画面回答。有角度清单时先算素材数，另算展示模块与成品。主图围绕实售 SKU，副图表达使用和细节，A+ 按当前站点、类型及模块拆画布；涉及上架硬规格时记录运营提供的后台模板或当前官方依据。若是内部试样，明确试样规格。
3. **出图前选最省返工的方法。** 直接沿用合适的实拍；只改背景或细节时使用图片编辑。需要新构图时按制作卡调用图像工具。对每个参考文件先看内容，绑定确切文件和用途。对外观风险大的图优先出样核对；多图可复用共享事实与视觉方向，逐张用自己的目的、角度和文案。用户只点名一张时，其他卡保持原状态。
4. **实际生成。** 在当前 Codex 有内置生图能力时，使用该能力及其支持的本地图片引用。生成完成后把原生输出保存到项目；若要导出其他尺寸，保留原始文件、记录导出方式和像素。用实际输出创建版本。工具暂不可用时记失败原因，保留制作卡，继续其他可做项。没有文件的图不能列为已生成。
5. **针对底图改。** 局部编辑首先传入指定版本的实际图片，把允许修改的对象、范围和周边保护项写清；需要时再附同角度实拍。仅尺寸任务先检查画幅和产品边缘，用确定性图像处理保比例导出。若反馈指向多种版本，仅澄清产生歧义的图。新版本关联父版本。
6. **查实物、查文件。** 逐张与实拍并排核对轮廓、关键部件、表面、颜色、文字、功能与场景。改字时放大比较文字框外的产品，要求实物细节完全保真时优先给原图留独立文字层。展示收纳或连接时，核对物件与具体部位的遮挡关系；哪一格、能否装下无法从画面判断的，记为示意并指出需要哪张实拍补证。交付像素与原生输出像素分别核对，保留放大记录。对不合格的图给出具体位置与修法；技术通过、视觉结果、用户选定分开记录。用时和重跑次数来自本次实际任务。

## 任务记录与恢复

每个 SKU 一个工作目录。图号在其中唯一；同图位的不同颜色使用不同图号，例如 `DETAIL-BLUE`。在 `job.json` 记录本次计划交图，`card` 指向已保存的制作卡。这里是可改的例子：

```json
{"schema":1,"sku":"示例型号","shots":[{"id":"DETAIL-BLUE","variant":"Blue","card":"cards/DETAIL-BLUE.md","spec":{"format":"PNG","width":1600,"height":1600}}]}
```

在项目里执行下列命令时，将 `工具` 替换为本 Skill 的 `scripts/jobs.py` 路径，将 `清单` 替换为该 SKU 的 `job.json` 路径。Python 需要安装 Pillow。

```text
python3 工具 --manifest 清单 status
python3 工具 --manifest 清单 register DETAIL-BLUE --version 1 --file 导出图.png --raw 原生图.png
python3 工具 --manifest 清单 register DETAIL-BLUE --version 2 --parent 1 --file 修订图.png
python3 工具 --manifest 清单 check DETAIL-BLUE --version 2
python3 工具 --manifest 清单 drift DETAIL-BLUE --version 2 --edit-box 340 110 940 395
python3 工具 --manifest 清单 check
python3 工具 --manifest 清单 fail DETAIL-BLUE --reason "生成中断，已有制作卡"
```

交付图即原生图时省略 `--raw`。运行 `status` 再决定哪些卡应续做；老版本留在原目录。快照 `card.md` 里写的相对路径以登记记录 `record.json` 的 `card` 所在目录为基准。运营选定情况及视觉核对记录写入 SKU 的修订/交接记录，最新候选和已选底图分别列出。若用户只要导出一张，用该图号核验即可；整套交付时对整个清单执行检查。交付链接指向实际文件。

局改前记下允许改动的位置。新旧原生图同尺寸时，可用 `drift` 比对新版与其父版。示例中的四个数字要换成本图允许修改的左、上、右、下坐标，均按方向校正后的原生像素，右端和下端不含在框内。工具只读，给出框外各通道平均绝对差及完全相同像素的比例。再并排看关键结构和面料，按这一张卡的保留要求判定。
